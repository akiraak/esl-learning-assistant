# 執筆画面: AI 返信の英文ブロックにコピーボタンを出す

## 目的・背景

執筆画面（`/admin/writing/:id`）の AI 相談チャットでは、修正後の英文や言い換えの例文が返ってくる。
いまは選択してコピーするしかなく、紙（本文）へ写すのに手間がかかる。
「修正後の英文」などのまとまりを、ボタン一つでコピーできるようにする。

## 対応方針

「まとまり」をどう決めるかが要点。AI の返信は自由な Markdown なので、
**英文のまとまりは必ずコードフェンス（```）で囲ませ**、それを 1 グループとして扱う。

1. `compositionChat.ts` のシステムプロンプトに、修正後の英文・例文・言い換えは
   ``` で囲んだブロックで示す旨を追加する（説明の日本語は外に書かせる）。
2. `compositionView.ts` の CSS で、返信内の `pre`（＋既存履歴のための `blockquote`）を
   等幅のコード塊ではなく「紙に近い英文カード」として見せる（本文と同じ serif）。
3. カードの右上に小さな「コピー」ボタンを重ね、押すと中身のテキストを
   `navigator.clipboard.writeText` でコピーする。使えない環境では隠しテキストエリア +
   `document.execCommand('copy')` に落とす。押した直後は「コピーしました」に変えて戻す。
4. ボタンは JS で後付けする（`decorateCopyTargets`）。サーバが埋めた既存履歴と、
   送信後に `replyHtml` で差し込む新しい返信の両方で同じ関数を通す。
   コピーする文字列はボタンを含まない元の要素から取るため、ボタン挿入前に控える。
5. 印刷時はボタンを出さない。

## 影響範囲

- `backend/src/compositionChat.ts`（システムプロンプト1項目の追加）
- `backend/src/compositionView.ts`（執筆画面の CSS・スクリプト）
- サーバ API・DB・他画面への変更なし。既存履歴（フェンス無し）はボタンが付かないだけで従来通り表示される。

## テスト方針

- `backend/test/compositionChat.test.ts`: システムプロンプトにコードフェンス指示が含まれること。
- `backend/test/compositionView.test.ts`: 執筆ページにコピーボタンを付けるスクリプトと CSS が含まれること。
- `npm test`（backend）で回帰がないことを確認。
- 手動: AI に修正案を出させ、ボタンでコピーできること・既存履歴が壊れないことを確認。
