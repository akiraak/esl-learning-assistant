# 執筆画面: 紙を横いっぱいに広げ、AI 欄との境界をドラッグで動かす

## 目的・背景

執筆画面（`/admin/compositions/:id`）は左に紙、右に AI 相談チャットの 2 ペイン。
現状は紙が `max-width: 44em` で中央寄せのため、画面が広いほど左右に余白が余り、書ける幅が伸びない。
また AI 欄の幅は 420px 固定で、紙を広く使いたいときも AI の回答をじっくり読みたいときも調整できない。

## 対応方針

1. `.sheet` の `max-width` を外し、紙をペイン幅いっぱいに広げる（左右の中央寄せ余白を廃止）。
2. `.split` の列指定を `minmax(0,1fr) / 仕切り / var(--chat-w)` に変え、間に細い仕切り（リサイザー）を置く。
3. 仕切りを Pointer Events でドラッグして `--chat-w` を更新する。幅は
   `280px 〜 min(720px, ウィンドウ幅 - 360px)` にクランプし、紙が潰れないようにする。
4. 確定した幅を `localStorage`（キー: `composition.chatWidth`）に保存し、次回表示時に復元する。
   保存値も同じ関数でクランプしてから適用する（ウィンドウ幅が変わっていても壊れないように）。
5. 幅が変わると本文の折り返しが変わるので、ドラッグ中は `autogrow()` を呼び直し、
   綴りポップオーバーは閉じる。
6. 縦積みになる狭い画面（`max-width: 900px`）と印刷時は仕切りを隠し、1 列に戻す。
7. キーボード操作（← →）でも動かせるよう `role="separator"` + `tabindex="0"` を付ける。

## 影響範囲

- `backend/src/compositionView.ts`（`renderCompositionEditorPageHtml` の CSS・HTML・スクリプト）のみ。
- サーバ側の API・DB・他画面への変更なし。

## テスト方針

- `backend/test/compositionView.test.ts` に、生成 HTML に仕切り要素と幅の保存キーが含まれることの確認を追加。
- `npm test`（backend）で既存テストの回帰がないことを確認。
- 手動: ドラッグで境界が動くこと・リロード後も幅が保たれること・狭い画面で縦積みに戻ることを確認。
